# Integration Plan: unified multi-protocol VPN setup repo

## Goal

Integrate the three packages from `vpnpackages/` alongside the existing OpenVPN code into a single, uniformly structured repo with:

- One directory per protocol, each with consistent server/client/templates/docs layout
- A single `configure.sh` (kconfig-style TUI via `whiptail`) that collects all parameters and writes `config.env`
- Top-level `install-server.sh` and `install-client.sh` that call per-protocol scripts sequentially
- Shared library in `common/lib.sh`
- Unified `__VAR__` template placeholder style across all protocols

## Design decisions

### Template placeholder style
Unify to `__VAR__` (double underscores) across all four protocols.  
The existing OpenVPN templates use `%%%VAR%%%` — these will be converted.  
Rationale: `__VAR__` is already used by Shadowsocks and sing-box packages; `sed` expressions are simpler without escaping `%`.

### Config file
A single `config.env` at repo root, sourced by all scripts with `source "$(dirname "$0")/../../config.env"` (adjusted per depth).  
Variable names are prefixed per protocol: `OVPN_`, `SS_`, `WG_`, `SB_`.  
The file is `chmod 600` on write (contains passwords and private keys).  
Add `config.env` and `*/generated/` to `.gitignore`.

### Crypto generation
Generated at `protocol/server/configure.sh` time, not during `configure.sh` (the TUI only collects user intent, not random material).  
Exception: WireGuard and sing-box generate keys during their `configure.sh` and append to a `generated/secrets.env` inside the protocol dir, which is sourced by `apply.sh` and `client/configure.sh`.

### common/lib.sh exports
- `require_root`
- `check_package` / `install_package` (deduped from utils.sh)
- `render_template src dst` — sed-based `__VAR__` substitution sourcing `config.env`
- `log_info` / `log_err`

### kconfig-style TUI
Uses `whiptail` (pre-installed on Ubuntu; fallback message if missing).  
Menu flow:
1. Main menu (--menu): navigate to each section
2. **Common** — server public IP; which protocols enabled (--checklist)
3. **OpenVPN** — port, protocol, subnet, cipher, cert type, DH type, TLS mode, compression
4. **Shadowsocks** — port, cipher method, password (auto-gen offered), timeout, local ports
5. **WireGuard** — interface name, port, VPN CIDR, client routing mode, NAT, PSK
6. **sing-box REALITY** — port, SNI host, UUID (auto-gen), short_id (auto-gen), log level, MTU
7. **Save & exit** — writes config.env, shows summary

Radio lists for mutually exclusive options (cipher, cert type, routing mode).  
Password boxes for secrets; offer auto-generation with `openssl rand`.

## Implementation phases

### Phase 1 — Repo skeleton and common library
**Tasks:**
1. Create directory tree: `common/`, `openvpn/`, `shadowsocks/`, `wireguard/`, `singbox-reality/` with `server/`, `client/`, `templates/`, `docs/` subdirs
2. Write `common/lib.sh` — extract `isRoot`, `check_package`, `install_package` from existing `utils.sh`; add `render_template`, `log_info`, `log_err`
3. Add `.gitignore` entries: `config.env`, `*/generated/`, `*/easy-rsa/`, `deploy.env`

### Phase 2 — OpenVPN migration
**Tasks:**
1. Copy `templates/*.template` → `openvpn/templates/*.tpl`; convert `%%%VAR%%%` → `__VAR__` placeholders
2. Split existing `utils.sh` functions into `openvpn/server/install.sh` (install_prerequisites, install_easy_rsa_from_source), `configure.sh` (configure_openvpn_server, create_server_config_file, create_client_template), `add-client.sh` (add_client), `start.sh`, `stop.sh`
3. Update all scripts to source `common/lib.sh` and `config.env`; use `render_template` instead of inline sed
4. Retire top-level `vpn.sh` and `utils.sh` (or leave as thin shims pointing to new locations)
5. Write `openvpn/docs/README.md`, `ARCHITECTURE.md`, `CONFIG_REFERENCE.md`

### Phase 3 — Shadowsocks migration
**Tasks:**
1. Copy templates from package `server/config.json.tpl`, `ubuntu-client/config.json.tpl`, `android/config.json.tpl` → `shadowsocks/templates/` with unified naming
2. Write `shadowsocks/server/install.sh` (from package's `server/install.sh` — drops interactive-deploy dependency, sources config.env instead)
3. Write `shadowsocks/server/configure.sh` — calls `render_template` for server config; calls `server/start.sh` or leaves that separate
4. Write `shadowsocks/server/start.sh`, `stop.sh`
5. Write `shadowsocks/client/install.sh` — from package `ubuntu-client/install.sh`; extract `create-user.sh` logic inline
6. Write `shadowsocks/client/configure.sh` — renders client config template; no interactive prompt, reads config.env
7. Copy `ubuntu-client/start-socks.sh`, `stop-socks.sh`, `start-transparent.sh`, `stop-transparent.sh` → `shadowsocks/client/`; update to source config.env for ports
8. Write docs (based on package's existing docs, deduplicated and aligned to new structure)

### Phase 4 — WireGuard migration
**Tasks:**
1. Write `wireguard/templates/server.conf.tpl` and `client.conf.tpl` using `__VAR__` placeholders (the package generates configs inline in the script; extract the here-docs into actual template files)
2. Write `wireguard/server/install.sh` (from `scripts/install_server_deps.sh`)
3. Write `wireguard/server/configure.sh` — reads config.env for all WG_ vars; generates server and client keypairs; optionally generates PSK; stamps templates → `wireguard/generated/`; saves keys to `wireguard/generated/secrets.env` (chmod 600)
4. Write `wireguard/server/apply.sh` (from `scripts/apply_server_config.sh`); sources generated/secrets.env
5. Write `wireguard/server/start.sh`, `stop.sh`, `status.sh`
6. Write `wireguard/client/install.sh` (from `scripts/install_client_deps.sh`)
7. Write `wireguard/client/configure.sh` — writes `generated/client_linux.conf` and `generated/client_android.conf`; runs `qrencode` if available
8. Write `wireguard/client/apply.sh`
9. Write docs

### Phase 5 — sing-box REALITY migration
**Tasks:**
1. Copy templates → `singbox-reality/templates/` (already well-structured)
2. Write `singbox-reality/server/install.sh` (from `bin/install-server-deps.sh`)
3. Write `singbox-reality/server/configure.sh` — reads config.env SB_ vars; auto-generates x25519 keypair via `xray x25519` if available, else requires keys in config.env; auto-generates UUID and short_id if not set; stamps xray-server template → `singbox-reality/generated/xray-server.json`; saves generated secrets to `singbox-reality/generated/secrets.env`
4. Write `singbox-reality/server/apply.sh` — copies generated config to `/usr/local/etc/xray/config.json`; `systemctl restart xray`
5. Write `singbox-reality/server/start.sh`, `stop.sh`
6. Write `singbox-reality/client/install.sh` (installs sing-box)
7. Write `singbox-reality/client/configure.sh` — stamps android and ubuntu-client templates using secrets from `generated/secrets.env`; writes `generated/singbox-android.json`, `generated/singbox-ubuntu-client.json`
8. Write `singbox-reality/client/run.sh` and install systemd unit
9. Write docs — include the Android DNS fix note (`sniff` before `hijack-dns`) as it's a non-obvious critical requirement

### Phase 6 — Top-level orchestration
**Tasks:**
1. Write `configure.sh` — whiptail TUI collecting all parameters listed in the Config variables section below; writes `config.env` with `chmod 600`; validates required fields (SERVER_PUBLIC_IP must be non-empty)
2. Write `install-server.sh`:
   ```
   source ./config.env
   for protocol in $ENABLED_PROTOCOLS; do
     ./$protocol/server/install.sh
     ./$protocol/server/configure.sh
     ./$protocol/server/apply.sh   # if it exists
   done
   ```
3. Write `install-client.sh` — same pattern for client side
4. Update top-level `CLAUDE.md` to reflect new structure

### Phase 7 — Documentation pass
**Tasks:**
1. Rewrite top-level `README.md` with new quickstart and protocol overview table
2. Ensure each `docs/CONFIG_REFERENCE.md` lists every `__VAR__` placeholder and the corresponding `config.env` variable
3. Each `docs/ARCHITECTURE.md` describes the traffic flow for server mode and client mode

## Config variables reference

All written to `config.env` by `configure.sh`.

### Shared
| Variable | Default | Notes |
|---|---|---|
| `SERVER_PUBLIC_IP` | — | Required; used by all client configs |
| `ENABLED_PROTOCOLS` | — | Space-separated: `openvpn shadowsocks wireguard singbox-reality` |

### OpenVPN (`OVPN_`)
| Variable | Default | Options |
|---|---|---|
| `OVPN_SERVER_NAME` | `myvpnserver` | Alphanumeric |
| `OVPN_WORKDIR` | `/root/servers/${OVPN_SERVER_NAME}` | |
| `OVPN_PORT` | `1194` | |
| `OVPN_PROTOCOL` | `udp` | `udp` / `tcp` |
| `OVPN_VPN_IP` | `10.9.0.0` | VPN subnet base |
| `OVPN_VPN_SUBNET_MASK` | `255.255.255.0` | |
| `OVPN_DNS1` | `8.8.8.8` | |
| `OVPN_DNS2` | `4.4.4.4` | |
| `OVPN_CIPHER` | `AES-128-GCM` | `AES-128-GCM` / `AES-256-GCM` / `AES-128-CBC` / `AES-256-CBC` |
| `OVPN_CERT_TYPE` | `ECDSA` | `ECDSA` / `RSA` |
| `OVPN_CERT_CURVE` | `prime256v1` | `prime256v1` / `secp384r1` / `secp521r1` |
| `OVPN_RSA_KEY_SIZE` | `2048` | `2048` / `3072` / `4096` |
| `OVPN_CC_CIPHER` | `TLS-ECDHE-ECDSA-WITH-AES-128-GCM-SHA256` | depends on CERT_TYPE |
| `OVPN_DH_TYPE` | `ECDH` | `ECDH` / `DH` |
| `OVPN_DH_CURVE` | `prime256v1` | same as CERT_CURVE options |
| `OVPN_DH_KEY_SIZE` | `2048` | if DH_TYPE=DH |
| `OVPN_HMAC_ALG` | `SHA256` | `SHA256` / `SHA384` / `SHA512` |
| `OVPN_TLS_SIG` | `tls-crypt` | `tls-crypt` / `tls-auth` |
| `OVPN_COMPRESSION_ENABLED` | `n` | `y` / `n` |
| `OVPN_COMPRESSION_ALG` | `lz4-v2` | if COMPRESSION_ENABLED=y |

### Shadowsocks (`SS_`)
| Variable | Default | Notes |
|---|---|---|
| `SS_SERVER_PORT` | `8388` | |
| `SS_PASSWORD` | auto-gen | `openssl rand -base64 32` |
| `SS_METHOD` | `chacha20-ietf-poly1305` | `chacha20-ietf-poly1305` / `aes-256-gcm` / `aes-128-gcm` |
| `SS_TIMEOUT` | `300` | Seconds |
| `SS_LOCAL_PORT` | `1080` | ss-local SOCKS5 |
| `SS_REDIR_PORT` | `1081` | ss-redir transparent |

### WireGuard (`WG_`)
| Variable | Default | Notes |
|---|---|---|
| `WG_INTERFACE` | `wg0` | |
| `WG_PORT` | `51820` | UDP |
| `WG_VPN_CIDR` | `10.66.66.0/24` | |
| `WG_SERVER_VPN_IP` | `10.66.66.1` | |
| `WG_CLIENT_NAME` | `client1` | |
| `WG_CLIENT_IP` | `10.66.66.2` | |
| `WG_DNS` | `1.1.1.1, 8.8.8.8` | |
| `WG_ROUTING_MODE` | `3` | 1=server-IP-only 2=vpn-subnet 3=full-tunnel 4=custom |
| `WG_CLIENT_ALLOWED_IPS` | `0.0.0.0/0, ::/0` | set if MODE=4 |
| `WG_ENABLE_NAT` | `yes` | PostUp/PostDown iptables MASQUERADE |
| `WG_ENABLE_PSK` | `yes` | PresharedKey between peers |

WireGuard keys (`WG_SERVER_PRIVKEY`, `WG_SERVER_PUBKEY`, `WG_CLIENT_PRIVKEY`, `WG_CLIENT_PUBKEY`, `WG_PSK`) are generated by `wireguard/server/configure.sh` and saved to `wireguard/generated/secrets.env`, not in `config.env`.

### sing-box REALITY (`SB_`)
| Variable | Default | Notes |
|---|---|---|
| `SB_PORT` | `443` | Xray listen port |
| `SB_SNI` | `www.cloudflare.com` | REALITY destination; must be a real TLS 1.3 host |
| `SB_UUID` | auto-gen | `uuidgen` |
| `SB_SHORT_ID` | auto-gen | `openssl rand -hex 8` |
| `SB_LOG_LEVEL` | `info` | `debug` / `info` / `warning` / `error` |
| `SB_TUN_MTU` | `1400` | sing-box TUN MTU |

REALITY keypair (`SB_REALITY_PRIVATE_KEY`, `SB_REALITY_PUBLIC_KEY`) is generated by `singbox-reality/server/configure.sh` via `xray x25519` and saved to `singbox-reality/generated/secrets.env`. If `xray` is not yet installed, `configure.sh` will prompt the user to run server install first or enter keys manually.
