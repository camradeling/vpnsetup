# sing-box REALITY Architecture

## Protocol stack

```
Client sing-box (TUN inbound)
  │  VLESS + REALITY + xtls-rprx-vision
  │  TCP to SERVER_PUBLIC_IP:SB_PORT
  │  Looks like TLS 1.3 handshake with SB_SNI host
  ▼
VPS Xray (VLESS inbound)
  │  freedom outbound
  ▼
Internet
```

## REALITY key exchange

REALITY uses an x25519 keypair (generated by `xray x25519`). The server holds the private key; the public key is distributed to clients. A `short_id` is an additional 8-byte identifier that must match between server and client. Together these prevent REALITY servers from being fingerprinted — a passive observer cannot distinguish the handshake from a genuine TLS 1.3 connection to the SNI host.

## TUN inbound (sing-box)

sing-box creates a virtual TUN interface (`tun0` on Android, `singtun0` on Ubuntu) with:
- `auto_route: true` — routes all traffic through TUN
- `auto_detect_interface: true` — finds the real outbound interface automatically

The server IP is excluded from TUN routing via a direct bypass rule to prevent a routing loop.

## DNS handling

sing-box's route engine processes packets in rule order:
1. `sniff` — classifies the packet protocol
2. `hijack-dns` — intercepts DNS protocol packets and handles them internally
3. Direct bypass for `SERVER_PUBLIC_IP/32`
4. Everything else → VLESS REALITY outbound

Without `sniff` before `hijack-dns`, DNS packets destined for the TUN's internal DNS resolver (e.g. `172.19.0.2:53`) are not classified as DNS and pass through as raw UDP — they go out via VLESS, fail, and DNS breaks completely.
